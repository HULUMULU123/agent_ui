# Банкротный анализ — рабочее место сотрудника (Gradio)

Загрузите банковскую выписку → парсер распознаёт таблицу операций → агент на **GigaChat-3-Ultra** оценивает каждую
операцию (приоритет ручной проверки, основание, документы, рекомендация) → сотрудник смотрит результат, правит
рекомендации и выгружает отчёт в Excel.

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt            # + requirements-optional.txt для PDF/Word, правового поиска, лемматизации
python app.py                              # http://127.0.0.1:7860
```

Без настроенного GigaChat приложение работает в режиме **«по правилам»** (предварительная оценка по типу операции,
направлению и периоду). Попробовать можно на странице «Анализы выписок» → «Попробовать на демо-выписке».

## Подключение GigaChat-3-Ultra

Страница **«Настройки»** (или переменные окружения / `.env`): `GIGACHAT_BASE_URL`, `GIGACHAT_CERT_FILE`,
`GIGACHAT_KEY_FILE`, `GIGACHAT_VERIFY_SSL` — корпоративный контур; либо `GIGACHAT_CREDENTIALS` + `GIGACHAT_SCOPE`.
Модель везде одна — `GigaChat-3-Ultra`: распознавание выписок, классификатор типов, оркестратор, анализатор, правовой поиск.
Кнопка «Проверить соединение» делает тестовый вызов. Настройки из интерфейса лежат в `data/settings.json` (права 0600).

## Как пользоваться

| Страница | Что делает |
|---|---|
| **Анализы выписок** | Загрузка файлов (Excel, CSV, Word, PDF, HTML, текст 1С), дата заявления о банкротстве, очередь и ход анализа, реестр, открыть / скачать / остановить / удалить |
| **Обзор** | KPI, движение средств, динамика по месяцам, категории, распределение по суммам, топ-5 контрагентов |
| **Операции** | Простая таблица (как в тетради): риск 0/1, дата, контрагент, назначение, сумма. Сначала операции с риском 1. Поиск, фильтры «риск» и «направление», выгрузка в Excel; клик по строке — карточка операции |
| **Карточка операции** | Основание проверки, факторы, обоснование, документы, связанные операции, чек-лист вопросов, **правка рекомендации**, решение и комментарий |
| **Рекомендации** | Таблица рекомендаций по отмеченным операциям — правится прямо в ячейке, «Сохранить правки»; исходный текст агента не теряется |
| **Контрагенты** | Обороты, категории, статус риска (с учётом памяти риска прошлых дел), операции контрагента |
| **Основания оспаривания** | Маршруты проверки (ст. 61.2, 61.3, 170 ГК…) с числом операций, суммой и вопросами |
| **Отчёты** | Выгрузки (вся выписка / отмеченные / с решением сотрудника), список работы сотрудника, качество распознавания |
| **Настройки** | GigaChat, параметры анализа, состояние баз |

Риск, как в тетради агента, только 0 или 1: **1 — требует проверки**, **0 — риска нет**. Это приоритет ручной проверки, а не вывод
о недействительности сделки. Если агент не смог проанализировать операцию, она получает риск 1 и учитывается отдельно как «Анализ не дал результата».

## Устройство

```
app.py                    точка входа (прежний интерфейс — app_legacy.py)
finapp/parser/            парсер выписок v2 (bank_parser.py генерируется из ноутбука) + service.py
finapp/agent/             агент v4 (GigaChat-3): prompts/catalog (из ноутбука), classifier, similarity, graph, pipeline, fallback, tools, risk_memory
finapp/jobs.py            очередь: парсер → агент → сохранение; прогресс в data/analyses/<id>/meta.json
finapp/store.py           анализы, решения и правки рекомендаций сотрудника (data/analyses/…)
finapp/analytics.py       статусы, KPI, агрегаты;  finapp/export.py — Excel
finapp/ui/                тема, HTML/SVG-блоки, страницы
tools/                    сборка модулей из ноутбуков, демо-выписка;  tests/ — pytest
```

Ноутбуки остаются источником правды для алгоритмов. После правки ноутбуков:

```bash
python tools/build_parser_module.py /путь/bank_parser_v2_clean.ipynb       # finapp/parser/bank_parser.py
python tools/extract_agent_data.py  /путь/agent_v4_gc3_no_chains.ipynb      # prompts.py и catalog.py
python -m pytest                                                           # 29 тестов, сеть и GigaChat не нужны
```

Опционально: нормативная база `faiss_normative_db/` и судебная практика `court_practice_storage/` в корне проекта
(пути — `NORMATIVE_INDEX_PATH`, `COURT_PRACTICE_STORAGE`). Без них правовой поиск пропускается. Память риска —
`risk_memory.db` (старая схема мигрирует автоматически с резервной копией `*.bak-*`).

Запуск в сети: `GRADIO_SERVER_NAME=0.0.0.0 GRADIO_SERVER_PORT=8080 python app.py`. Данные анализов — в `data/` (в git не попадают).
